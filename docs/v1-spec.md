# FRP Console 第一版规格

确认日期：2026-10-07。目标仓库：`https://github.com/cong86/frpc-ui`。

## 产品范围与成功标准

两端 UI、自动安装、手动配置、代理管理、Nginx 反代模板、分层验证与回滚。首批 Debian/Ubuntu/PVE LXC，amd64/arm64，原生 systemd 与 Docker Compose。

成功必须同时满足：FRP 独立于管理进程；配置不丢未知内容；操作可预览、冲突可拒绝、故障可恢复；验证各层分别报告；隔离测试矩阵通过。自动配对、集中下发、客户端热备、证书自动维护、通知、更多平台、FRPS 高可用均延期，仅预留接口。

## 页面

登录初始化、总览、客户端连接、客户端代理、服务端概览、服务端配置、配置变更、反代模板、验证日志、备份维护、操作审计。

客户端管理 TCP/UDP/HTTP/HTTPS 定义。服务端只观察注册代理，管理 FRPS 参数和允许端口策略；不远程改客户端。HTTPS 代理按 SNI 转发本地 TLS，Nginx TLS 终止后转发 HTTP 为独立模板，不能混淆。

## 配置归属

- FRP 配置文件及其引用是唯一配置来源。SQLite 只保存账户、元数据、操作、审计和加密恢复快照，不维护另一套自动回写的代理定义。
- 运行状态来自服务管理器、FRP 接口、日志和明确测试，不能从配置启用值推断。
- 新安装使用 TOML。INI 先只读识别，再生成迁移预览；不按扩展名猜格式。引用和模板依赖必须完整识别后才允许写入。
- 外部修改只通知，不能自动覆盖或加载。正式事务绑定全部依赖修订号及目标二进制版本；专属锁不能阻止不遵守协议的外部写入，接管须明确独占管理权。
- 未知字段、注释、非目标配置保留；无法保证则只读，不猜测删除。
- Docker 新部署使用目录挂载。现有单文件挂载需识别 inode，不能 rename 后假定容器已读到新文件。迁移与原地写入均须独立计划、备份、恢复与运行验收。
- 已有同步器、主备服务或其他配置写入者存在时先只读；本项目不接管其协调逻辑。

## 接口边界

Web API → ConfigStore / FRPAdapter / RuntimeAdapter / Installer / NginxAdapter / Verifier。

Web 使用低权限；系统执行器仅接受固定动作、登记实例及受限路径。浏览器不提交任意 Shell。FRP 管理 API 本机或专用容器网络访问；Web 容器不直接挂 Docker socket。

所有写操作：基线读取 → 候选 → 目标版本 verify → 脱敏差异及运行影响 → 确认 → 锁内复核 → 备份 → 写入 → reload/restart → 分层验证 → 必要时恢复。计划必须持久化并支持幂等查询；超时不重发写操作。

客户端代理可按版本能力 reload；公共参数默认 restart。FRPS 默认 restart。Token 变更人工协调两端。升级分别处理 Console 和 FRP，数据库迁移前保留一致快照。卸载 Console 默认保留配置、备份及既有 FRP；删除实例是独立操作。

## 安装器

环境预检 → 客户端/服务端/两者 → 新装/接管 → 手填/导入 → 地址/端口/Token/管理员 → 部署计划 → 安装 → 分层验证 → UI 链接与安装信息。

固定测试版本、下载校验、镜像摘要；识别重装不覆盖配置。LXC 不自动修改 PVE 宿主权限。接管不自动升级、修改防火墙、云安全组或已有 Nginx。Nginx 新站点独立文件，既有站点明确 include/补丁，完整上下文 nginx -t 通过后才加载，失败恢复；证书手动提供。

## 开发阶段

1. 规格与能力边界。
2. 配置、脱敏、冲突、备份、操作恢复及本地界面。
3. systemd 适配、自动安装与分层验证。
4. 客户端完整运行操作与日志。
5. 服务端运行查询、参数应用与恢复。
6. Compose 适配、接管及 inode 场景。
7. Nginx 完整上下文校验、加载与恢复。
8. 升级、卸载、两架构与故障测试矩阵。

当前实现覆盖第二阶段的基础闭环，后续各阶段不能因已有页面或模板标记完成。

## 验收清单

- [ ] Console 停止/崩溃/升级不影响 FRP 隧道。
- [ ] 多实例独立，不误操作其他实例。
- [ ] 四种代理增删改启停，文件与运行结果一致。
- [ ] 取消零修改，过期/冲突计划拒绝，重复请求幂等。
- [ ] INI 迁移可审查恢复，未知字段/注释/引用保留。
- [ ] 写入中断、reload/restart 失败和管理程序退出可核对恢复。
- [ ] Docker 目录及单文件挂载实际读到目标配置。
- [ ] 重装、接管、升级、回滚、卸载不误伤其他实例。
- [ ] 页面/日志/错误/审计/诊断不泄漏凭据；完整备份加密。
- [ ] Nginx 保留已有路由，校验失败不加载，加载失败可恢复。
- [ ] 各发行版/架构/方式形成实测矩阵，不以编译代替运行验收。

六层结果分别为安装就绪、进程运行、认证连接、代理注册、本地服务、实际业务。记录来源、时间、执行位置。UDP 需要协议响应；HTTP 检查目标状态/内容；WebSocket 检查握手与双向消息。未测显示未验证，服务器本机测试不能代替独立外网验收。
