# 原生安装与运行观测验证

2026-10-07（Asia/Singapore）；范围为上一轮两个 Debian 12 amd64 非特权 LXC。现有生产 FRP、主备与反代未修改。

## 实测

- 28 项默认 Go 测试。Windows 下 POSIX 权限测试明确 skip；两 LXC Linux 测试全部通过，无 skip。官方 verify 使用 FRP 0.71.0 实际二进制。
- Vue/TypeScript 构建、go vet、Linux amd64/arm64 构建；arm64 未实机运行。
- 客户端和服务端自动新安装：预检、脱敏预览、私有原始计划、SHA-256、官方 verify、低权限独立 systemd 单元、重复执行幂等。
- 额外 localhost 双角色新安装：FRPS 先启动，客户端认证及 TCP 注册成功，经隧道收到预期目标的 FRPS API 响应。验证后停用双角色测试单元，保留数据。
- 两主实例各登记一个实际角色；API 不含 Token/FRP 管理密码。
- 客户端六层全通过；服务端安装/进程/认证/注册/业务通过，本地服务未验证。
- TCP/HTTP 内容、UDP nonce、HTTPS SNI 与 CA 校验通过。主探针由各 Console 节点执行，不证明公网可达。
- 停止后端时进程/注册仍通过，本地服务/业务失败；恢复并等待真实监听后，两层重新通过。
- 配置计划取消后原文件不变。
- 停止两端新 Console，四种业务仍通过，FRPS/FRPC PID 不变。
- 模拟 systemctl enable 失败：新单元移除，数据保留，现有测试 FRPS PID 不变；未完成安装拒绝重放。
- 两端按地址独立命名 Cookie。同一个 cookie jar 登录两个端口后，两端仍分别认证。
- 实际 PTY 验证交互向导：隐藏 Token 输入、0600 私有计划、取消零安装、输入计划 ID 完成新安装。向导测试单元随后停用。

初次自动安装后发现 Cookie 的端口隔离问题，修复后更新 Console。最终代码再次通过本地检查、两个 Linux 容器相关测试和双角色新安装。

## 交付

新实例在独立 stage3 目录；上一轮配置、数据库、单元文件和私有数据归档保留。旧测试单元停用，新单元继续运行；LXC 开机自启关闭。临时 QA 管理员在收尾移除，用户可初始化自己的管理员。
