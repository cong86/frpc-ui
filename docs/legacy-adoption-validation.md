# 旧 INI 接入修复验证

版本：v0.1.0-preview.10，2026-10-07。

## 修复范围

FRPS 按内容识别 [common] 旧 INI，支持扩展名为 .toml 的文件；只读投影供页面和本机管理 API 使用，不迁移原文件。解析器使用官方 FRP 同版 INI 依赖和读取选项。dashboard_pwd、Token、插件凭据及其重复引用脱敏；未知字段保留。旧 INI 客户端、模板求值、字段插值和配置迁移不在本次范围。

运行方式默认自动识别，仅查询 frps/nginx 同名 Docker 容器及对应 systemd 服务。唯一且可确认的目标作为可修改的默认值；冲突、权限不足和自定义名称要求手动选择。找到了登记目标或配置路径，不代表进程正常或配置已被加载。

## 自动化与隔离验证

- Windows Go 测试及 go vet，Linux amd64 的 config、observe、installer 测试；覆盖 INI/BOM/CRLF、源修订、未知字段、密码脱敏、拒绝写入、安全语法诊断、TLS/非回环 API 不降级、唯一/冲突/权限不足的运行方式识别。
- 前端类型检查和嵌入资源构建，16 项安装入口测试、11 项 Gitee 同步测试，Linux amd64/arm64 构建。
- WSL 隔离环境实际使用官方 FRPS/FRPC 0.71.0，FRPS 从名为 frps.toml 的旧 INI 启动，建立回环 TCP 业务隧道。真实伪终端通过安装入口、配置自动查找、预览确认、独立 UI 与采集 timer 安装；API 凭据脱敏，低权限网页不能读取原配置，写入请求被拒绝。
- 原 FRPS PID、配置哈希和测试业务响应保持正常；重复成功计划不重启管理 UI，外部配置变化拒绝安装，模拟新服务启动失败只移除新增单元；停止 Console 后原隧道仍可访问。

Docker 的运行方式与挂载算法由固定命令 fixture 覆盖；Nginx 为磁盘配置和日志 fixture，未在本次测试中启动真实 Nginx。arm64 仅构建。云服务器仅只读核对格式、文件权限与同名运行目标，未安装新版 Console、修改原配置或重启 FRPS/Nginx。隔离结果不能代替生产安装验收。
